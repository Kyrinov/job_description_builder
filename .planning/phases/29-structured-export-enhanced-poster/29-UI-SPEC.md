Each new button:
- Class: `btn--export` (identical styling to DOCX/PDF/Copy buttons)

## Button State Contract

Each export button (JSON + CSV) must implement these states using the existing exportAs() async pattern:

| State | Visual | Trigger |
|-------|--------|---------|
| Idle | `.btn--export` default — panel background, line border, ink text | Default render |
| Hover | `.btn--export:hover` — accent-line border, accent-soft background, accent-deep text, translateY(-1px) | CSS :hover (already defined) |
| Loading / in-flight | Button text changes to "Downloading…"; button gains `disabled` attribute; opacity 0.45 (match `.btn--primary:disabled` pattern) | After fetch() call, before blob resolves |
| Success | Toast appears: "job-description-data.json downloaded" or "job-description-data.csv downloaded" for 2600ms; button returns to idle | After URL.createObjectURL + anchor click |
| Error | Toast appears with error copy (see Copywriting Contract); button returns to idle | On non-ok HTTP response |

Implementation note: `exportAs()` in app.jsx manages loading state via a `setExporting` flag passed as prop to `ReviewState`. Alternatively, local `useState` inside `ReviewState` per-button is acceptable. The contract is: the button must not be clickable while its own download is in flight. Other export buttons remain independently clickable.

## Interaction Contract: exportAs() extension

Phase 29 extends `exportAs(kind)` in app.jsx with two new kind values:

```
kind === 'json'  → POST /api/wd/{wd_id}/export/json  → filename: {title}.json
kind === 'csv'   → POST /api/wd/{wd_id}/export/csv   → filename: {title}.csv
```

Filename construction: `${(record.title || 'work-description').toLowerCase().replace(/\s+/g, '-')}.{ext}`

Guard: `if (!wd_id)` — same guard as DOCX/PDF. No OG/level guard for JSON/CSV (manager-track WDs without confirmed_og must succeed per SEXP-04 success criterion).

Response handling: identical to DOCX pattern — `resp.blob()` → `URL.createObjectURL` → anchor click → `URL.revokeObjectURL`. No special handling needed for JSON MIME type vs binary — the Blob pattern is MIME-agnostic.

## Copywriting Contract

| Element | Copy |
|---------|------|
| JSON button label | Export JSON |
| CSV button label | Export CSV |
| JSON download in-flight | Downloading… |
| CSV download in-flight | Downloading… |
| JSON success toast | "Structured data downloaded (JSON)" |
| CSV success toast | "Structured data downloaded (CSV)" |
| JSON error toast | "JSON export failed — {detail}. Try again or contact support." |
| CSV error toast | "CSV export failed — {detail}. Try again or contact support." |
| Empty state (no wd_id) | "Save your work description first before exporting." (reuse existing toast — no change) |
| Manager export note | No special copy — manager sees same buttons; classification fields show "[ADVISOR TO COMPLETE]" in the downloaded file, not in the UI |

No destructive actions in this phase. No confirmation dialogs required.

Icon guidance (inline SVG, 17×17, `viewBox="0 0 20 20"`):

- JSON button: curly-brace icon — `<text x="2" y="14" font-size="12" font-family="monospace" fill="currentColor">{}</text>` or a minimal path depicting `{ }` brackets
- CSV button: table/grid icon — `<rect x="3" y="5" width="14" height="10" rx="1" fill="none" stroke="currentColor" stroke-width="1.6"/><path d="M3 9h14M9 5v10" stroke="currentColor" stroke-width="1.4"/>` 

If inline SVG paths are difficult to render legibly at 17px, fall back to a generic download arrow icon consistent with the other export buttons.

## Accessibility Contract

- All new buttons must have explicit text labels (no icon-only buttons)
- `aria-disabled="true"` during loading state alongside `disabled` attribute
- `aria-live="polite"` region for toast notifications (existing `.toast` implementation already covers this — no change needed)
- Tab order: JSON and CSV buttons follow Copy in DOM order; no `tabIndex` manipulation needed
- Minimum touch target: 44×44px (the existing `.btn--export` at `padding: 12px 18px` with 14.5px text satisfies this at typical viewport widths)
