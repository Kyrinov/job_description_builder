## Spacing Scale

The project uses an 8-point base grid. All values are multiples of 4px.
Inherited from Phase 18 UI-SPEC without change.

| Token | Value | Usage in this phase |
|-------|-------|---------------------|
| xs | 4px | Icon-to-text gaps, `.qual-sub-k` bottom margin, `.qual-error` margin-top and gap, `.amend-indicator` margin-left |
| sm | 8px | Gap between qual fields, amendment panel internal gap, `.prov__tag` padding, `.amend-panel__actions` gap and margin-top |
| md | 16px | Default element spacing, `.input-zone` gap, amendment textarea gap |
| lg | 24px | Section `margin-top` between doc sections |
| xl | 32px | Layout-level gaps |

- Qual textarea rows: `min-height: 88px` — matches existing `textarea.tf` rule in

- Amendment indicator dot: `width: 8px; height: 8px` — follows the `--line` dot
  rhythm used elsewhere (phase bar: 4px; live dot: 7px; prov dot: 5px). 8px chosen
  for visibility at section-header size.

### New elements for Phase 19

#### A. OG-matched Qualification Prefill (QualEditor — data layer)

The existing `QualEditor` component reads `QUAL_DEFAULT` from `data.jsx`. Phase 19
replaces the static `QUAL_DEFAULT` export with an OG-group-keyed defaults map and a
`getQualDefault(og_code)` function. This is documented here as a visual contract item
because it controls what text appears in the textareas on step mount.

**Prefill values per OG group (exact strings — verbatim from TBS Qualification
Standards reference text as encoded in `QUAL_STANDARDS` constant in `app/data/constants.py`):**

| OG Code | Education prefill | Experience prefill |
|---------|-------------------|--------------------|
| EC | A degree from a recognized post-secondary institution, with acceptable specialization in economics, sociology or statistics, or a field of study related to the duties of the position (environmental science, public policy, or a natural or social science field). | Significant experience in policy analysis, economic research, or program evaluation relevant to the duties of the position. |
| AS | A secondary school diploma or an acceptable combination of education, training and/or experience. | Experience in administrative, financial, or operational support functions relevant to the duties of the position. |
| IT | Successful completion of two years of an acceptable post-secondary educational program in computer science, information technology, information management or another specialty relevant to the position. | Experience in information technology functions relevant to the duties of the position. |
| FI | A bachelor's degree from a recognized post-secondary institution with a specialization in accounting, finance or a related field. | Significant experience in financial management, financial analysis, or accounting relevant to the duties of the position. |
| default | A degree or diploma from a recognized post-secondary institution in a field relevant to the duties of the position, or an equivalent combination of education and experience. | Experience performing duties relevant to the position. |

**`getQualDefault(og_code)` logic:** look up `og_code` in the keyed map; fall back to
`default` if not found.

**How prefill reaches `QualEditor`:** `initialAnswer` in `components.jsx` currently
returns `QUAL_DEFAULT` for `type === 'quals'`. Phase 19 changes this to call
`getQualDefault(record.confirmed_og?.og_code)` so the correct text lands in the
textarea when the quals step first mounts.

**Editing model:** the prefill is an editable starting point. The user may modify or
replace it freely. The `QualEditor` input contract is unchanged; `onChange` fires on
every keystroke.

#### D. Amendment Note Panel (AMEND-01)

The amendment note panel is an inline expandable panel that opens below the section
header of any JD section in review state. It is NOT a modal or overlay.

**Trigger:** An "Add note" icon button rendered inside `.sec__h` in review state,
to the left of the "edit" hover label. The button is always visible in review state
(not just on hover) so the interaction is discoverable.

**Panel layout:**
```
┌─────────────────────────────────────────────────────────┐
│ [Section N] Section Name        · src pill  [↑] [note+] │  ← .sec__h, note+ is .amend-btn
├─────────────────────────────────────────────────────────┤
│  Note for: {section name}                               │  ← .amend-panel (inline below header)
│  ┌───────────────────────────────────────────────────┐  │
│  │ textarea (.tf) — free text                        │  │
│  └───────────────────────────────────────────────────┘  │
│  [Save note]  [Discard note]        N characters        │
└─────────────────────────────────────────────────────────┘
```

**State model:** `amendmentPanels` is a `useState` object in `DocumentPane` (or passed
down from `app.jsx`):
```js
// keyed by section key ('id', 'ov', 'du', 'cls', 'q', 'drf')
{
  [sectionKey]: {
    open: boolean,        // panel is expanded
    text: string,         // current textarea value
    saved: string | null, // last saved note text (null if none saved for this section)
  }
}
```

**Amendment button icon:** A pencil/note icon. Use an inline SVG path:
`<path d="M14 3l3 3-9 9H5v-3L14 3z" fill="none" stroke="currentColor" stroke-width="1.6" stroke-linecap="round" stroke-linejoin="round"/>` (20×20 viewBox).

**Saved note display:** When a note has been saved for a section, the panel (when

`.amend-indicator` dot remains visible on the section header.

**Panel open/close transition:** Use the existing `rise` animation class on the

On success: set `saved = text`, close panel, show toast "Note saved for {section name}."

**Discard action:** close panel without saving; reset textarea to `saved` value (or
empty if no saved note).

and non-empty. It is always visible in review state when a note exists — not only on
hover.

**Position in `.sec__h`:** after `.amend-btn`, before any trailing content.

**Accessibility:** Add `aria-label="Amendment note exists"` to the `.amend-indicator`
span.

## Interaction Contracts

### Qualification Step (QUAL-01, QUAL-02)

| Interaction | Behavior |
|-------------|----------|
| Step mounts | `QualEditor` receives `value = getQualDefault(record.confirmed_og?.og_code)`; textareas display OG-matched prefill text; "Finish & review" button state is `disabled=false` because prefill is non-empty |
| User edits either textarea | `onChange` fires; `QualEditor` updates value; button state updates live |
| User clears a textarea completely | Field goes empty; "Finish & review" button becomes `disabled`; inline `.qual-error` message appears on blur |
| User refocuses emptied field and types | `.qual-error` disappears as soon as the field has content |
| Both fields non-empty | "Finish & review" button enabled (`disabled` attribute removed) |
| Submit (button click or Cmd/Ctrl+Enter) | `onCommit()` fires; `step.apply` patches `record.quals`; `qualsVisited = true` is set; Section 5 fills with `freshWash` animation; transcript settles with `settle` animation |

### Amendment Panel (AMEND-01)

| Interaction | Behavior |
|-------------|----------|
| Condition: `reviewing === false` | `.amend-btn` NOT rendered in any section header; no amendment UI visible |
| Condition: `reviewing === true` | `.amend-btn` rendered in all section headers (Position Identification, Position Overview, Key Responsibilities, Classification & Evaluation, Essential Qualifications, Defence Results Linkage if present) |
