## Spacing Scale

The project uses an 8-point base grid. All values are multiples of 4px.

| Token | Value | Usage in this phase |
|-------|-------|---------------------|
| xs | 4px | Icon-to-text gaps, inline provenance dot spacing |
| sm | 8px | Duty card internal gap, chip row gap |
| md | 16px | Default element spacing, input zone gap |
| lg | 24px | Section `margin-top` between doc sections |
| xl | 32px | Layout-level gaps |
| 2xl | 40px | Provenance footer `margin-top` (matches `.prov`) |
| 3xl | 52px | Doc paper top padding (matches `.doc`) |

**Exceptions for Phase 18:**
- Duty selector cards: `padding: 12px 14px` (matches existing `.duty-sug` — 12px is
  within the grid tolerance for card padding).
- Orphan warning badge: `padding: 4px 8px` (follows `.prov__tag` rhythm).
- "Add your own duty" submit button: min touch target 44px height (accessibility).

### New elements for Phase 18

#### A. NOC Duty Selector (conversation pane, duty step)

The existing `DutyBuilder` component currently drives from `DUTY_SUGGESTIONS` (static
OG-keyed arrays). Phase 18 replaces the suggestion source with FTS5-matched verbatim
NOC duties fetched from the backend for the confirmed NOC code.

**Interaction model:**
1. On step mount, fetch `GET /api/noc/{noc_code}/duties` (or equivalent FTS5 endpoint
   returning verbatim duty strings for the confirmed NOC code).
2. Render each duty as a `.duty-sug` card with `.duty-sug__plain` showing verbatim text.
3. Selected state: `.duty-sug.is-sel` — same accent border + background as existing
   selection pattern.
4. Selection count badge: show `N selected` in Spline Sans Mono 10px, `color:
   var(--ink-faint)`, above the duty list. Updates live as cards are toggled. No
   separate popover or drawer needed.
5. "Add your own duty" row: retain existing `.duty-add` row exactly. Advisor-added
   duties receive `advisor: true` and are rendered with `.duty-sug__tag` in gold.
6. Submit CTA: `.btn--primary` labelled **"Add to description"**. Disabled until at
   least 1 duty is selected. Placed in the `.actions` row at `margin-left: 43px`
   (aligned with existing input zone).

**ProvenanceTag display on selected NOC cards:**
When a NOC duty card is in `.is-sel` state, show the `.duty-sug__tag` row (reused
class) with content: `NOC 2021 · {noc_code}`. Use `--gold` color (already applied by
`.duty-sug__tag`). This is the visible surface of JD-02.

**Advisor-added duty tag:**
Already implemented via `.duty-sug__tag` with gold color. Phase 18 changes the tag
label to `advisor-added` (not `refined for the description`). This is the visible
surface of JD-03.

#### B. Orphan Warning Badge (document preview, per duty)

Rendered inside the Key Responsibilities section on flagged `.doc-duty` items at review
time (JD-04). Appears below the duty text, inline.

**Anatomy:**
```
[⚠ badge text]
  ↳ Rationale citation text
```

**CSS specification (new class `.orphan-badge`):**
```css
.orphan-badge {
  display: inline-flex;
  align-items: flex-start;
  gap: 6px;
  margin-top: 6px;
  font-family: var(--mono);
  font-size: 10px;
  line-height: 1.4;
  color: oklch(0.58 0.14 35);       /* amber-orange */
  background: oklch(0.97 0.035 50); /* warm near-white */
  border: 1px solid oklch(0.88 0.07 42);
  border-radius: var(--radius-sm);  /* 9px */
  padding: 5px 9px;
}
.orphan-badge__icon {
  flex: 0 0 auto;
  margin-top: 1px;
}
.orphan-badge__body {}
.orphan-badge__label {
  font-weight: 600;
  letter-spacing: 0.03em;
  text-transform: uppercase;
  font-size: 9px;
}
.orphan-badge__cite {
  display: block;
  margin-top: 3px;
  font-weight: 400;
  letter-spacing: 0;
  text-transform: none;
  font-size: 10px;
  color: oklch(0.50 0.10 35);
}
```

**Icon:** Use a small warning triangle inline SVG (path: a triangle with exclamation,
16×16 viewBox). Render via the existing `Icon` helper at `size={13}`.

**Position:** Render immediately after the duty `<li>` text, as a child `<div>` within
the same `<li>`. The `.doc-duty` `padding-left: 22px` already provides indent; the
badge inherits it.

**Trigger:** Only shown when `d.orphan === true` on the duty object (set by the backend
orphan check response). Only visible in review state.

#### C. Section 3 Ghost State (Key Responsibilities — no duties yet)

Reuse existing pattern exactly. Specified for executor clarity:

```jsx
<Ghost lines={2} />
<p className="ghost-note">
  Select duties from the NOC list — they will appear here, verbatim and traceable.
</p>
```

This replaces the existing ghost note copy ("Your responsibilities will appear here,
formally worded.") from document.jsx line 253. The new copy is the Phase 18 contract.

#### D. Provenance Footer — Phase 18 additions

The existing `.prov` / `.prov__tag` pattern is reused. Phase 18 adds two new tag
conditions to `provTags` in `DocumentPane`:

1. `'NOC 2021'` — already present when `hasDuties`. No change needed.
2. `'Advisor-added'` — already present when `r.duties.some(d => d.advisor)`. No change
   needed.
3. After Phase 18, the provenance footer tag list for a fully-filled JD will be:
   `NOC 2021 | EC JES 2017 | TBS OG Definitions | Advisor-added` (where applicable).

The `src` pill on Section 3 header: when duties are present, show `NOC 2021` (already
coded as `src={hasDuties ? 'NOC 2021 · refined' : null}`). Phase 18 changes this to
`src={hasDuties ? 'NOC 2021' : null}` — remove "· refined" since duties are now
verbatim, not LLM-refined.

## Interaction Contracts

### Duty Selector Step

| Interaction | Behavior |
|-------------|----------|
| Step mounts | Fetch NOC duties for `confirmed_noc_code`; show loading state (3 × `.ph-line` shimmer while fetching) |
| Duty card click | Toggle `.is-sel`; update selection count badge; update `value` array |
| All cards deselected | "Add to description" button disabled |
| At least 1 selected | Button enabled |
| Advisor-adds duty | Appended to bottom of list with `advisor: true`; gold `.duty-sug__tag "advisor-added"` visible immediately |
| Submit | `onChange(selectedDuties)`; conversation step commits; Section 3 populates with `freshWash` animation |
| NOC fetch error | Toast error message; duty list shows static fallback message (not shimmer) |

### Section 3 — Key Responsibilities (document preview)

| State | Rendering |
|-------|-----------|
| No duties yet | 2 shimmer lines + ghost note copy (see copywriting above) |
| Duties present, not review | `.doc-duty` list; NOC duties get blue diamond; advisor duties get gold diamond |
| Duties present, review state | As above + `.sec--editable` clickable; hover shows "edit" label |
| Orphan detected (review only) | `.orphan-badge` rendered inside flagged `<li>` below duty text |

### Orphan Warning (review time only)

| Trigger | The backend POST `/api/wd/{id}/orphan_check` returns flagged duty IDs + rationale |
|---------|---|
| No orphans | No badges rendered; silent pass |
| Orphan(s) found | Badge rendered per flagged duty; no blocking gate; advisor can proceed |
| Badge content | Label "ORPHAN WARNING" + verbatim rationale from `d.orphan_rationale` |

### Section Click-to-Edit (DOC-04)

This contract governs all 5 sections, not just Section 3.

| Condition | Behavior |
|-----------|----------|
| `reviewing === false` | `.sec--editable` class NOT applied; `onClick` handler NOT bound; no hover "edit" label |
| `reviewing === true` | `.sec--editable` class applied; hover shows "edit" in `.sec__h::after`; clicking calls `onEditStep(stepKey)` |
| Jump target for Section 3 | `onEditStep('duties')` — maps to the duties step in STEPS array |

### Provenance Footer (DOC-05)

The footer updates after every step commit. The live update is implicit — `DocumentPane`
derives `provTags` from the `record` prop on every render. No special logic required
beyond what already exists in document.jsx lines 365–371.

## Accessibility Notes

- All duty selector cards are `<button type="button">` elements (keyboard navigable,
  Enter/Space activates) — matches existing `.choice` / `.duty-sug` pattern.
- Orphan badge uses `role` not needed (informational only, not interactive).
- Selection count badge is visually updated; wrap in `aria-live="polite"` span so screen
  readers announce count changes.
- `.btn--primary` disabled state: `disabled` attribute must be set (not just
  `opacity: 0.45`) so keyboard/screen reader users cannot activate it.
- `prefers-reduced-motion` block in styles.css already disables all animations globally.
