## Decisions Made

- **Empty-div anchor approach.** Instead of editing `jes_factor.html` to add `id="failed-factors"` on the first failed card, the partial is left untouched and an empty `<div id="failed-factors"></div>` is rendered BEFORE the first failed card in `jes_scores.html`. Rationale: simpler, keeps `jes_factor.html` reusable for the per-card swap, and the empty div is invisible to the user (zero layout impact).
- **Regex-parsed error → structured dict.** The validator returns free-form strings like `"JES factor 'X' is incomplete (level=1, points=None) — ..."`. The route parses these once into `{factor_name, level, points, reason}` dicts. Rationale: the template can then iterate structured data and emit anchor links to the right cards.
- **Pre-validation gated on `wd.stage == 'jes_scored'`.** Earlier stages (input, noc_mapped, og_classified, jd_drafted) should NOT show a "factors are incomplete" alert because the JES sheet hasn't been generated yet. The route checks stage before computing `failed_factors`.
- **Regex fallback.** If the regex doesn't match an error string (e.g., the validator message format changes in the future), a fallback dict with `factor_name='(unknown factor)'` is appended so the error is still surfaced — nothing is silently lost.
- **No new CSS tokens.** Layer 12 uses existing `--color-success-text`, `--color-error-text`, `--color-link`, `--color-text-muted` custom properties with literal hex fallbacks. New tokens can be added in a later refactor; for now the visual style is consistent with Layer 10/11.

5. User clicks an item or scrolls to the failed card — sees the Retry/Override buttons (already in place from 08.1-02)
6. User clicks Retry — the card swaps in place with the new score (or stays in error state if the LLM still fails)
7. User clicks Override — the override form expands inline, user fills it in, submits
8. Card now shows the advisor-adjusted badge (`jes-factor-card--advisor` + `.jes-advisor-badge` styled by Layer 12)
9. User clicks "Continue to Export" — export succeeds because the validator now accepts `advisor_adjusted=True` factors (D-08.1-03)
