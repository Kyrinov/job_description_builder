## Color

All Phase 4 tokens inherited. Phase 5 adds one new semantic token.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | #FFFFFF | Page background, card backgrounds | Inherited |
| Secondary (30%) | #F5F5F5 | Input background, footer background | Inherited |
| Accent (10%) | #1A4A8A | Primary CTA, confirmed OG card border, active wizard step | Inherited |
| Destructive | #C0392B | Error states, invalid-level error text | Inherited |
| **Warning (new)** | **#7D5C00** text on **#FFF8E1** background | AS/EC alert banner only |

**Accent reserved for (Phase 5 additions):**
- "Confirm [OG code]" submit button background on each OG card
- Confirmed OG card border (2px solid #1A4A8A, same as confirmed NOC card pattern)
- Level selector focus ring

**Warning color rationale:** The AS/EC alert is not a destructive action (no data is deleted) and
not a neutral informational note. It is a policy decision boundary that, if ignored, produces a
legally indefensible classification. Amber (#FFF8E1 surface, #7D5C00 text) signals "proceed with
deliberate attention" — semantically distinct from both the GC-blue accent (primary action) and red
destructive. Contrast: #7D5C00 on #FFF8E1 = 7.1:1 (AAA compliant).

**New CSS custom properties to add to `:root`:**

```css
--color-warning-bg:   #FFF8E1;
--color-warning-text: #7D5C00;
--color-warning-border: #F9A825;
```

**Source:** Phase 4 tokens — 04-UI-SPEC.md §Color. Warning color — Claude's Discretion (no
upstream artifact specifies AS/EC alert color).

## Interaction Contract

### Primary Visual Anchor

The AS/EC alert banner (when present) is the primary visual anchor for this step — it renders
above the OG candidate cards and cannot be scrolled past without seeing it. The "OG Classification"
Display heading is the secondary anchor.

### Wizard Step: `templates/wizard/step_og.html`

Extends `base.html`. Entry point is `POST /api/og/classify` triggered from `noc_confirmed.html`.

**States:**

| State | Trigger | Visual |
|-------|---------|--------|
| Loading | noc_confirmed "Continue to Classification" POSTs /api/og/classify | `htmx-indicator` spinner visible: "Classifying occupational group..." |
| Results — policy duties detected | POST returns asec_alert + candidates | Warning banner above 3 OG cards |
| Results — no policy duties | POST returns candidates only | 3 OG cards, no banner |
| Empty | Pipeline returns 0 candidates | Empty state message in `#wizard-step` |
| Error | 422 or 5xx from /api/og/classify | Error message in `#wizard-step` |
| Confirmed | Advisor submits level + confirm button | `og_confirmed.html` replaces `#wizard-step` |

**HTMX bindings:**

| Form / element | Binding |
|----------------|---------|
| noc_confirmed.html continue form | `hx-post="/api/og/classify"`, `hx-target="#wizard-step"`, `hx-swap="outerHTML"`, `hx-indicator="#og-spinner"` |
| Each OG card confirm form | `hx-post="/api/og/confirm"`, `hx-target="#wizard-step"`, `hx-swap="outerHTML"` |

**Important:** `noc_confirmed.html` currently does NOT have the continue form. Wave 0 must add it.
Verified absent from `templates/partials/noc_confirmed.html` (the partial ends after the status
`<div>` with no form element). Add:

```html
<form hx-post="/api/og/classify"
      hx-target="#wizard-step"
      hx-swap="outerHTML"
      hx-indicator="#og-spinner">
    <input type="hidden" name="wd_id" value="{{ wd_id }}">
    <span id="og-spinner" class="htmx-indicator">Classifying occupational group...</span>
    <button type="submit" class="button button--primary">Continue to OG Classification</button>
</form>
```

### OG Candidate Cards Layout

`.og-candidates` uses CSS Grid: `grid-template-columns: repeat(auto-fit, minmax(280px, 1fr))`.
- On wide desktop (≥900px): 3 cards side-by-side.
- On tablet (~600-899px): 2 cards + 1 below, or 1 per row depending on minmax calculation.
- On narrow / mobile (<600px): 1 card per row (natural column collapse).

No JavaScript needed for responsive layout. The `minmax(280px, 1fr)` grid handles it natively.

Each `.og-card` renders top-to-bottom:
1. Card header — `[OG code] OG Name` at Heading size (20px/600)
2. Definition section — `<h4>Definition</h4>` at Label size + `<blockquote>` + `<cite>`
3. Inclusions section — `<h4>Relevant Inclusions</h4>` at Label size + `<blockquote>`
4. Exclusions section — `<h4>Relevant Exclusions</h4>` at Label size + `<blockquote>`
5. Confirm form — level `<select required>` + "Confirm [OG code]" button

**Card visual rules:**
- Card border: 1px solid #D0D0D0 (same as `.noc-card`)
- Card padding: var(--space-lg) (24px)
- Card border-radius: var(--radius-md) (8px)
- Confirmed card: border changes to 2px solid #1A4A8A (same pattern as `.noc-card.confirmed`)
- `<blockquote>`: border-left 3px solid #D0D0D0, padding-left var(--space-md), font-style normal, color var(--color-text-muted)
- `<cite>`: display block, font-size var(--text-sm), color var(--color-text-muted), margin-top var(--space-xs)

### AS/EC Alert Banner Layout

`.asec-alert` renders ABOVE `.og-candidates`, always. It is never hidden, collapsed, or
conditionally positioned.

- Background: var(--color-warning-bg) = #FFF8E1
- Border: 1px solid var(--color-warning-border) = #F9A825
- Border-left: 4px solid var(--color-warning-border) (stronger visual anchor)
- Border-radius: var(--radius-md)
- Padding: var(--space-lg)
- role="alert" (accessibility — screen reader announces immediately on HTMX swap)

`.asec-comparison` uses CSS Grid: `grid-template-columns: 1fr 1fr`, gap: var(--space-md).
Collapses to single column below 600px.

`.asec-card--as` and `.asec-card--ec` are visual containers (no border — the parent alert provides
the visual boundary). Each contains:
- `<h4>` heading at Label size
- Sub-label `<p>` at 14px/400 (body-sm), color var(--color-text-muted)
- `<blockquote>` with verbatim citation text
- `<cite>` source attribution

### Level Selector Behavior

Each OG card has an independent `<select name="og_level" required>`. Rules:
- Default selected option: `<option value="">Select level...</option>` (empty value, triggers native
  HTML validation on submit attempt)
- Populated options: `<option value="{{ level }}">{{ og_code }}-{{ level }}</option>` for each
  level in `candidate.available_levels`
- Form uses native HTML5 `required` — no JavaScript validation needed
- Button label: "Confirm [OG code]" where `[OG code]` is the specific code (e.g., "Confirm EC")
- On submit: HTMX posts `wd_id`, `og_code` (hidden input), `og_level` (select value)

### Loading State

`#og-spinner` uses `.htmx-indicator` class — inherits the CSS rule already in `main.css`:
```css
.htmx-indicator { display: none; }
.htmx-request .htmx-indicator { display: inline-block; }
.htmx-request.htmx-indicator { display: inline-block; }
```

The spinner appears inline next to the "Continue to OG Classification" button in
`noc_confirmed.html` during the classify call. No separate spinner needed on individual confirm
buttons — the confirm call is fast (DB write only, no LLM).

### og_confirmed.html Pattern

Mirrors `noc_confirmed.html` structure:
- Wraps in `<div id="wizard-step" class="og-confirmed-banner" role="status">`
- Heading (20px/600): "OG Confirmed"
- Confirmation line (16px/400): "[og_code] — [og_name]"
- Level line (16px/400): "Level: [og_level]"
- Note (14px/400, muted): "This selection has been saved. Proceed to JD generation."
- CTA form: `hx-post="/api/jd/generate"` (Phase 6 endpoint, rendered as disabled placeholder
  button if Phase 6 is not yet implemented)

## Accessibility Constraints

Inherited from Phase 4, plus Phase 5 additions:

- `.asec-alert` uses `role="alert"` — screen reader announces immediately when HTMX swaps it in.
- Each `<select name="og_level">` has an explicit `<label>` with `for` attribute.
- All three confirm forms are independent — each is a full `<form>` element, not a shared form with
  radio buttons. This ensures keyboard users can tab into each card's confirm flow independently.
- The AS/EC two-column comparison uses `<div>` grid (not `<table>`) — no table accessibility
  complexity needed for a two-panel layout without row/column relationships.
- Contrast: #7D5C00 on #FFF8E1 = 7.1:1 (AAA). All inherited Phase 4 contrast values unchanged.
- Minimum button height: 44px (inherited `min-height: 44px` from Phase 4 button CSS).
