## Visuals

### Focal Point — Sub-Group Disambiguation Screen

The `.asec-alert` block is the primary visual anchor on the sub-group disambiguation screen. It appears above the `.choices` list, establishing the reading order: alert text first (title, body, citation), then choice cards. The alert's `var(--accent-soft)` background provides sufficient contrast against the `var(--panel)` conversation pane to draw the advisor's eye before any choice card receives focus.

No additional visual hierarchy elements are introduced by Phase 21. The split-pane layout (`grid-template-columns: minmax(440px, 0.92fr) 1.08fr`) is unchanged.

## Interaction States

### Sub-Group Disambiguation Flow (OGX-07)

1. Advisor selects an OG candidate from the `.choices` list
2. If `confirmed_og` is NU, SW, or ED: API response includes `subgroup_alert` (new field analogous to `asec_alert`)
3. Frontend renders `.asec-alert` block above a second `.choices` list of sub-group options
4. Advisor selects a sub-group — stored as `confirmed_sub_group` on WorkDescription
5. Conversation proceeds to OG level selection using the confirmed sub-group

**No blocking behavior.** The sub-group picker is an additional step within the existing OG confirmation flow, not a hard gate. Pattern: same as current ASEC alert which renders above the candidate list.

### JES Scorecard Rendering (OGX-05/06)

Two rendering paths — both use existing `.jes` CSS, no new visual contract:

- **Point-rating groups (FB, FS, LP, MT, LC, SW-SCW):** render `.jes__row` per factor with `.jes__name`, `.jes__deg`, `.jes__pts`. Same as EC path.
- **Level-description groups (NU, PS, NT, PO, WP, SW-CHA, ED sub-groups):** render single `.jes__total` line (no per-factor rows). Same as FI/AS/IT path.

The `ClassBlock` component in `components.jsx` already branches on `jes_scores.length > 0`. No JSX changes needed for the two-path rendering — only backend data changes.
