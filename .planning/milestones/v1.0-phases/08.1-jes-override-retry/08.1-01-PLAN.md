<objective>
Add the service-layer recovery paths for incomplete JES scoring: per-factor retry (re-runs the LLM for one factor) and per-factor advisor override (manually sets level + points + rationale). Update `validate_export_readiness` to accept advisor-overridden factors so the export gate honors the override as a resolution.

Purpose: Closes the gap identified during Phase 8 UAT where the export validator blocks a WD with incomplete factors and there is no recovery path. The data model already has `advisor_adjusted` / `advisor_adjusted_level` / `advisor_adjustment_rationale` fields; this plan makes them functional.

- `app/services/jes_service.py` gains `async retry_jes_factor(...)` and `def override_jes_factor(...)`
- `app/services/export_service.py` `validate_export_readiness` updated to honor `advisor_adjusted`
- New tests in `tests/test_jes_scoring.py` and `tests/test_export.py` covering retry, override, and the validator change

The retry service should:
- Re-fetch the WD
- Find the factor in `wd.jes_scores` by name
- Re-fetch the factor_row from `jes_factors` table (same as score_jes does)
- Re-run only that single LLM call
- Build a new JESFactorScore
- Replace the old score in `wd.jes_scores` (in place)
- Recompute `wd.jes_total_points`
- Save the WD

The override service should:
- Re-fetch the WD
- Find the factor in `wd.jes_scores` by name
- Validate level (int >= 1) and rationale (>= 10 chars)
- Build a new JESFactorScore with:
  - level=level, points=points, rationale=rationale (form values)
  - advisor_adjusted=True, advisor_adjusted_level=level, advisor_adjustment_rationale=rationale
  - provenance=ProvenanceTag(source_type="ADVISOR", source_id=f"{og_code}/{factor_name}", source_version="advisor manual override", retrieved_date=date.today(), modified_by_advisor=True)
- Replace the old score in `wd.jes_scores`
- Recompute `wd.jes_total_points`
- Save the WD

WorkDescription field access for retry/override (see app/models/work_description.py):

- wd.jes_total_points: Optional[int]
- wd.confirmed_og: Optional[str] (needed to look up the factor row)

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| caller → retry_jes_factor(wd_id, factor_name) | wd_id and factor_name cross into the service; both flow into parameterized SQL loads (wd_store, jes_factors lookup) |
| caller → override_jes_factor(...) | form values (level, points, rationale) cross into the service; rationale is user text stored on the WD |
| WorkDescription.jes_scores → DOCX render | advisor-adjusted factors render with provenance.source_type="ADVISOR"; the D-06 advisor-added marker in the template covers this |

## ASVS L1 Threat Register (STRIDE)

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08.1-01 | Injection (SQLi) | wd_id, factor_name | mitigate | All queries use parameterized SQL (wd_store, jes_factors lookup). No string formatting into SQL. |
| T-08.1-02 | Tampering | override level/points | mitigate | level must be int >= 1 (server-side validation); points is optional int (allow None for effort factors); rationale must be >= 10 chars (advisor justification is the audit trail). All validated in override_jes_factor before save. |
| T-08.1-03 | Repudiation | override provenance | mitigate | advisor_adjusted=True is recorded on the JESFactorScore; provenance.source_type="ADVISOR" with retrieved_date=date.today() creates an immutable audit record. The DOCX export manifest shows both the original LLM source and the ADVISOR source. |
| T-08.1-04 | DoS | LLM retry storm | mitigate | retry_jes_factor only re-runs ONE factor per call (not the whole 10-factor pipeline). The UI only shows Retry on failed factors, not on every card. No bulk-retry endpoint exists. |
| T-08.1-05 | Information Disclosure | override rationale in DOCX | accept | rationale is the advisor's own justification text on their own WD; single-user local app (Out of Scope: multi-tenant per REQUIREMENTS.md). |
| T-08.1-06 | Elevation of Privilege | override without validation | mitigate | wd.stage must be 'jes_scored' (cannot override on exported WDs); rationale must be >= 10 chars; level must be int >= 1. Server-side validation enforced. |
