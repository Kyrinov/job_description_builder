# Phase 08.1: Plan 01 — Service-layer recovery paths for incomplete JES scoring

**Per-factor retry (LLM re-run) and per-factor override (advisor manual set) in jes_service; export validator accepts advisor-overridden factors**

## Accomplishments

- `async retry_jes_factor(wd_id, factor_name, db_path)` re-runs the LLM scoring call for one factor; replaces the old score (order-preserved) in `wd.jes_scores`; recomputes `jes_total_points`; saves the WD; on LLM failure the old score is preserved and `ValueError` is raised with the failure reason.
- `def override_jes_factor(wd_id, factor_name, *, level, points, rationale, db_path)` (SYNC) sets `advisor_adjusted=True`, `advisor_adjusted_level=level`, `advisor_adjustment_rationale=rationale.strip()`, and flips `provenance.source_type` to `"ADVISOR"` with `retrieved_date=date.today()` and `modified_by_advisor=True`. Server-side validation: `level` must be `int >= 1`, `rationale` must be `>= 10 chars` after strip.
- `validate_export_readiness` now skips the `level==-1` / `points is None` block check when `s.advisor_adjusted is True` (D-08.1-03). Unoverridden failures still block. Error message updated to mention "apply advisor override" so the user knows about the recovery path.
- 9 new tests cover the contract: 4 retry + 5 override, plus 3 validator tests. Full suite: 174 passed, 1 pre-existing skip, 0 regressions.

## Decisions Made

- **LLM-failure preservation:** `retry_jes_factor` catches the LLM exception, logs a warning, and re-raises as `ValueError(f"Retry failed for {factor_name!r}: {exc}")` — but does NOT replace the old score in the WD. Rationale: retry should not lose progress; the user keeps the sentinel until they either retry again or apply an override. The route layer will map this `ValueError` to HTTP 422.
- **Sync override service:** `override_jes_factor` is SYNC (no `asyncio.to_thread`) because there's no I/O latency to hide — just a Pydantic field update and a SQLite write. Mirrors the pattern of other sync services in the codebase.
- **Order-preserving replacement:** both retry and override use `new_scores = list(wd.jes_scores); new_scores[factor_index] = new_score` rather than a filter-and-append. Rationale: the WD's `jes_scores` order is the UI's render order; preserving it avoids the "factor moved to the bottom" UX bug.
- **Validator short-circuit:** the check is `if s.advisor_adjusted: continue` BEFORE the `level==-1 / points is None` check. Rationale: an advisor-overridden factor that still has the sentinel `level=-1` / `points=None` (theoretical) should still pass — the override is the source of truth.
