## Decisions Made

- **Single-card partial = top-level template, NOT a macro.** The plan originally suggested a macro; the route layer's analysis showed a top-level template is simpler (route can call `templates.TemplateResponse` directly without rendering the macro module first). The plan's Task 3 notes this decision explicitly.
- **HTMX error re-render pattern.** Validation errors (`rationale < 10 chars`, `level out of 1-4`) re-render the form partial with the error message inline AND return 422 — so the user sees the error in context without a full page reload. Lookup errors (factor not found, wrong stage) return 404/422 as JSON.
- **GET /form is a pure render.** No service call — just a template render. The user clicked Override, this returns the form to fill in. Keeps the surface area small and avoids unnecessary DB reads.
- **Points parsing.** Empty string from the form maps to `None` (for effort factors with no numeric scale); non-empty string is parsed as `int`; non-integer string returns 422 with an inline error.
