# Phase 4 — UI Design Contract

> Visual and interaction contract for the NL→NOC Mapping wizard step. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none — plain CSS served as static file |
| Preset | not applicable |
| Component library | none — hand-rolled HTML + CSS |
| Icon library | none — text labels only in Phase 4 |
| Font | system-ui, -apple-system, "Segoe UI", Helvetica Neue, Arial, sans-serif |

**Rationale:** The project stack is FastAPI + Jinja2 + HTMX 2.0.4 + Alpine.js 3.14.8 — not React/Next.js/Vite. shadcn does not apply. The base.html template has zero styling today; Phase 4 introduces the first advisor-facing UI surface and establishes the CSS foundation that later phases extend. A plain CSS file at `app/static/css/main.css` loaded from `base.html` is the correct approach — no build step, no CDN stylesheet dependency beyond the already-committed HTMX and Alpine.js CDN scripts.

**Source:** RESEARCH.md §Standard Stack, RESEARCH.md §Pattern 5, base.html inspection.

## Interaction Contract

### Primary Visual Anchor

Primary visual anchor: the Display-size page heading ("NL→NOC Mapping") and the "Find NOC Candidates" button (accent background, #1A4A8A). These two elements are the first focal point the advisor's eye lands on. All other elements — the textarea, card grid, and loading indicator — are subordinate to this anchor pair.

### Wizard Step: `templates/wizard/step_noc.html`

This is the only full-page template for Phase 4. It extends `base.html`.

**States:**

| State | Trigger | Visual |
|-------|---------|--------|
| Idle | Page load | Textarea (empty), "Find NOC Candidates" button enabled |
| Loading | HTMX POST in-flight | Button disabled, `htmx-indicator` spinner visible: "Searching NOC database..." |
| Results | HTMX swap complete | NOC candidate cards appear below the form in `#noc-results` |
| Empty | Pipeline returns zero candidates | Empty state message in `#noc-results` |
| Error | 422 or 5xx from API | Error message in `#noc-results` |
| Confirmed | Advisor clicks "Confirm this NOC" | Confirmation banner replaces `#wizard-step`; "Continue to Classification" CTA visible |

**HTMX bindings (from RESEARCH.md §Pattern 5):**

- Form: `hx-post="/api/noc/map"`, `hx-target="#noc-results"`, `hx-swap="innerHTML"`, `hx-indicator="#spinner"`
- Confirm button: `hx-post="/api/noc/confirm"`, `hx-target="#wizard-step"`, `hx-swap="outerHTML"`

### NOC Candidate Card: `templates/partials/noc_results.html`

Each card renders:
1. Card header — NOC code, unit group title, TEER badge (inline, accent background)
2. Matched duty statements — bulleted list of verbatim NOC text
3. LLM justification — collapsible `<details>` element (collapsed by default; Alpine.js not needed — native HTML)
4. Confirm button — full-width, accent colour, text "Confirm this NOC"

**Card visual rules:**
- Card border: 1px solid #D0D0D0 (secondary)
- Confirmed card (after selection): border changes to 2px solid accent (#1A4A8A) with a "Confirmed" text badge
- Duty list items: 14px body, 1.4 line-height, left-padded 16px
- Rationale text inside `<details>`: 14px body, colour #555 (muted)

### Loading State

The `#spinner` element uses class `htmx-indicator` which HTMX shows during requests. CSS rule:

```css
.htmx-indicator { display: none; }
.htmx-request .htmx-indicator { display: inline-block; }
.htmx-request.htmx-indicator { display: inline-block; }
```

Button disabled state during loading: set `hx-disabled-elt="find-btn"` on the form (HTMX 2.x attribute).

### Error Rendering

The `/api/noc/map` route returns HTTP 422 with `{"detail": "..."}` for empty FTS shortlist. The HTMX partial for errors uses the same `#noc-results` target. The server renders a Jinja2 error fragment:

```html
<div class="error-state" role="alert">
    <strong>Error:</strong> {{ error_message }}
</div>
```

CSS for `.error-state`: border-left 4px solid destructive (#C0392B), padding-left: var(--space-sm), colour #C0392B.

## CSS Architecture

**File:** `app/static/css/main.css`
**Loaded from:** `base.html` `<head>` block.

**Layers (in document order):**
1. CSS reset (box-sizing, margin reset)
2. Design tokens as CSS custom properties on `:root`
3. Base typography (body, h1-h3, p, ul, li)
4. Layout (header, main, footer)
5. Form elements (label, input, textarea, button)
6. Component classes (.noc-card, .teer-badge, .error-state, .empty-state, .confirmation-banner)

## Accessibility Constraints

- All form inputs have explicit `<label>` elements with `for` attribute matching input `id`.
- Error messages use `role="alert"` so screen readers announce them after HTMX swap.
- Loading spinner uses `aria-live="polite"` on the `#noc-results` container so assistive technology announces when results arrive.
- Buttons use semantic `<button type="submit">` — not `<div>` or `<a>` styled as buttons.
- Colour contrast: #1A4A8A on #FFFFFF = 7.5:1 (AAA compliant). #C0392B on #FFFFFF = 5.1:1 (AA compliant).
- Minimum touch target: all buttons at least 44px height (set via `min-height: 44px` in CSS).
